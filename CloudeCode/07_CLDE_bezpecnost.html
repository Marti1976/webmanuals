Bezpečnost

Claude Code má přímý přístup k vašemu filesystému, Gitu a příkazové řádce. To je jeho síla — ale také zdroj rizik, pokud se bezpečnost podcení.

Rizika a hrozby — co se může pokazit

Claude Code není nebezpečný nástroj, ale má reálný vliv na váš systém. Než pochopíte rizika, těžko je budete řešit. Zde jsou nejčastější problémy, ke kterým dochází:

1. Neúmyslné smazání nebo přepsání souborů

Agent při refaktoringu "vyčistí" soubory, které považuje za zastaralé — ale vy jste je stále potřebovali. Nebo přepíše konfiguraci produkčního serveru, protože jste spustili Claude Code ve špatném adresáři.

2. Odhalení citlivých dat v kontextu

Claude Code čte soubory v projektu — včetně .env souborů s hesly, AWS klíčů v konfiguracích nebo databázových connection stringů. Tyto hodnoty se pak nacházejí v kontextovém okně a mohou být zahrnuty do promptů odesílaných Anthropic API.

3. Nežádoucí Git operace

Agenti mohou pushovat přímo do main větve, mazat větve nebo vytvářet commity s citlivými daty (pokud je náhodou zahrnete do kontextu).

4. Eskalace oprávnění přes shellové příkazy

Pokud povolíte volné spouštění bash příkazů, může Claude (v teorii, zejména při prompt injection útocích přes načtená data) provést operace, které jste nezamýšleli. Toto riziko je nízké při normálním použití, ale při práci s nedůvěryhodným kódem nebo daty roste.

Zdokumentovaný incident z praxe

V roce 2025 vývojář spustil Claude Code s --dangerously-skip-permissions na projektu s připojenou produkční databází. Claude v rámci "cleanup" úkolu smazal tabulky, které považoval za dočasné. Záloha nebyla. Ztracena data za 2 dny práce.

Oprávnění nástrojů — klíčové nastavení

Systém oprávnění v Claude Code funguje na principu allowlist a denylist. Vše, co není explicitně povoleno, Claude Code před provedením potvrdí s uživatelem. Denylist blokuje příkazy úplně — Claude nemůže ani navrhnout jejich použití.

Doporučená základní konfigurace

.claude/settings.json — bezpečná konfigurace
{
  "permissions": {
    // Co Claude smí dělat BEZ potvrzení
    "allow": [
      "Bash(npm run test)",
      "Bash(npm run test:unit)",
      "Bash(npm run lint)",
      "Bash(npm run build)",
      "Bash(git status)",
      "Bash(git diff)",
      "Bash(git log --oneline -20)",
      "Bash(git add -p)",
      "Read(**)"   // čtení libovolného souboru
    ],
    // Co Claude NESMÍ nikdy provést
    "deny": [
      "Bash(git push origin main)",
      "Bash(git push --force*)",
      "Bash(git reset --hard*)",
      "Bash(rm -rf*)",
      "Bash(DROP TABLE*)",
      "Bash(sudo*)",
      "Bash(chmod 777*)",
      "Bash(curl* | bash)",
      "Bash(npm publish*)"
    ]
  }
}

Jak fungují wildcards v deny pravidlech

Hvězdička * na konci pravidla matchuje cokoli za ní. Bash(git push --force*) zablokuje jak git push --force tak git push --force-with-lease origin main. Pravidla jsou porovnávána s celým příkazem, ne jen začátkem.

Zlaté pravidlo

Deny list je vaše pojistka. Do allowlistu patří jen příkazy, které jsou bezpečně reverzibilní nebo pouze čtou data. Vše, co mění produkční data nebo repo bez možnosti vrácení, patří do denylists.

Ochrana citlivých dat a API klíčů

Claude Code čte soubory v pracovním adresáři. Pokud váš projekt obsahuje .env soubory, konfigurační soubory s hesly nebo certifikáty, jsou tyto hodnoty součástí kontextu posílaného do API.

Co nikdy nemá být v kontextu Clauda

  • .env soubory s produkčními hodnotami — databázová hesla, API klíče třetích stran, JWT secret
  • AWS / GCP / Azure credentials — soubory ~/.aws/credentials nebo service account JSON
  • SSL certifikáty a privátní klíče — soubory .pem, .key, .p12
  • OAuth tokeny v konfiguračních souborech
  • Databázové dumps s reálnými uživatelskými daty (GDPR)

Praktické opatření — .claudeignore

Stejně jako .gitignore říká Gitu co ignorovat, soubor .claudeignore říká Claude Code co nečíst. Vytvořte ho v kořeni projektu:

.claudeignore
# Citlivé konfigurace
.env
.env.local
.env.production
.env.*.local

# Credentials a klíče
*.pem
*.key
*.p12
secrets/
.secrets/

# Databázové dumps
*.sql
dumps/
backups/

# Logy s potenciálně citlivými daty
logs/
*.log

Co musí být v .gitignore (bezpečnostní minimum)

Toto je základní bezpečnostní minimum pro každý projekt. Claude Code může navrhnout commitnutí souborů — pokud nejsou v .gitignore, je riziko odhalení reálné:

.gitignore — bezpečnostní minimum
# Nikdy do Gitu
.env
.env.*
!.env.example   # výjimka: vzorový soubor BEZ hodnot je OK

*.pem
*.key
*.p12
*.pfx

# AWS a cloud credentials
.aws/
credentials.json
service-account*.json

# IDE a lokální konfigurace
.claude/settings.local.json
Bezpečný vzor pro .env

Commitujte .env.example s ukázkovými (falešnými) hodnotami a komentáři — tým tak ví, jaké proměnné nastavit. Reálné hodnoty sdílejte přes password manager (1Password, Bitwarden) nebo secrets manager (AWS Secrets Manager, Vault).

Audit a logování

Claude Code loguje všechny provedené akce do adresáře ~/.claude/logs/. Logy obsahují timestamp, typ operace, soubory a příkazy. Pro týmy je auditování klíčové.

Čtení logů — příklady
# Zobrazit log dnešní session
cat ~/.claude/logs/session-$(date +%Y%m%d).json | python3 -m json.tool

# Hledat všechny bash příkazy v logu
cat ~/.claude/logs/*.json | grep '"type":"bash"' | jq '.command'

# Hledat zápisy souborů
cat ~/.claude/logs/*.json | grep '"type":"write"' | jq '.path'

Bezpečnostní doporučení pro týmy

  • Commitujte .claude/settings.json do repozitáře — celý tým sdílí stejná deny pravidla. Nikdo nemůže říct "já o tom pravidle nevěděl."
  • Nikdy --dangerously-skip-permissions na produkci — Tento přepínač deaktivuje veškerá bezpečnostní potvrzení. Použitelný jen v izolovaném testovacím prostředí.
  • Separátní API klíče pro Claude Code — Pokud platíte přes API, vytvořte dedikovaný klíč s monthly budget limitem v Anthropic Console. Nekompromituje ostatní systémy.
  • Sandbox pro neznámý kód — Při práci s externím kódem (open source contributions, code review) spouštějte Claude Code ve virtuálním prostředí nebo kontejneru.
  • Review agentních PR — Nikdy neautomaticky mergujte PR vytvořené agentem bez lidské kontroly. Agenti mohou udělat správné věci špatným způsobem.
  • Rotace API klíčů po incidentu — Pokud byl API klíč potenciálně odhalený (commit do public repo), okamžitě ho deaktivujte v Anthropic Console a vytvořte nový.
