Ceny & Plány

Claude stojí peníze. Ale ne všechno stojí stejně.

Existují tři způsoby, jak zaplatit za Claude — subscription (Pro/Max), API pay-as-you-go a Batch API. Každý má jinou cenu, limity a použití. Tady se orientujete správně.

Přehled plánů

Claude.ai Pro — $20/měs

Co dostanete: Přístup k aktuálnímu Claudovi (Sonnet 4.6 výchozí, Opus 4.7 dostupný), web UI, rate limits cca 80–120 promptů/den, paměť (memory) zachovávající kontext přes sessions.

Kdy se vyplatí: Začátečníci, osobní projekty, psaní, brainstorming. Pokud pracujete s Claudem méně než 3 hodiny denně, Pro je dostatečné.

Omezení: Rate limits jsou těsné pro development sessiony — pokud necháte session běžet delší dobu a posíláte mnoho promptů, můžete narazit na throttling.

Claude.ai Max — $100/měs (5×) a $200/měs (20×)

Co dostanete (5×): 5× vyšší rate limits, neomezený Sonnet (4.6), omezený Opus (4.7 — cca 50k tokens za den). Web UI, advanced features.

Co dostanete (20×): 20× vyšší rate limits, neomezený Sonnet i Opus, full access k extended thinking, AI features bez omezení.

Kdy se vyplatí: Profesionální dev, dlouhé session se složitými úkoly, agenti. Max 20× je ideální pro produktivitu — při počtu sessionů a délce promptů, kterou vývojáři obvykle mají, se vám vrátí mnohokrát.

Praktika: Pokud používáte Claude v průměru 5+ hodin denně na komplexní úkoly, Max se vyplatí. Pokud 2–3 hodiny, zvažte Pro + API pro specifické úlohy.

API (pay-as-you-go) — od $0.80 USD/MTok input

Co dostanete: Přímý přístup k modelům přes REST API (bez web UI), Batch API s 50% slevou, neomezené prompty (platíte jen za tokeny).

API sazby za tokeny

Tokeny nejsou rovnoměrně drahé. Každá operace — čtení, psaní, cache, paměť — má svou cenu. Zde je podrobný přehled:

OperaceCenaKdy se stane?
Vstup (input token)Základní sazbaVaše zpráva, soubory, kontext, systém prompt
Výstup (output token)2–5× vstupOdpověď Claudea, jakákoli délka
Cache reads0,1× vstupKdyž přečte znovu stejný obsah ze cache (prakticky free)
Cache writes1,25× vstupKdyž poprvé vloží soubor do cache (jednou)
Paměť (Memory)0,5× vstupAutomatické shrnutí cross-session (jednou za session)
Batch API discount50 % z input/outputPouze v Batch API, asynchronní zpracování
Praktický příklad: Cache ekonomika

Pošleš stejný 100KB PDF 10×: Poprvé = 125 tokenů (cache write), pak 9× po 10 tokenech (cache read) = 125 + 90 = 215 tokenů za vše. Bez cache = ~1250 tokenů. Úspora: 83 %.

Jak ušetřit náklady — čtyři konkrétní taktiky

1. Prompt caching — nejlevnější trik

Pokud máte dlouhý soubor (dokumentace, codebase, specifikace) a ptáte se ho 5+× na věci, cache je brutálně levné. Soubor se "přilepí" — každý další prompt jen přečte z cache za 10 % ceny.

Aktivace prompt cache v API
# Soubor se vloží do cache na 5 minut
curl https://api.anthropic.com/v1/messages \
  -H "anthropic-beta: prompt-cache-2024-07-31" \
  -d '{
  "model": "claude-opus-4-7",
  "messages": [{
    "role": "user",
    "content": [{
      "type": "document",
      "source": { "type": "base64", "media_type": "application/pdf", "data": "..." }
    }, {
      "type": "text",
      "text": "Jakou architekturu používá tato API?"
    }]
  }]
}'

# Druhý prompt — stejný soubor, cache hit
# Cena input tokenu klesne na 10 %

2. Batch API — až 50 % úspora

Máte noční běh s 1000 prompty? Nepoužívejte live API. Batch API je asynchronní, zpracuje se do 24 h a je o 50 % levnější. Vyplatí se naopak jen pro velké objemy nebo rutinní automatizaci.

Batch API setup — jednoduše
# Připravte soubor se všemi requesty (JSONL formát)
cat > batch.jsonl << EOF
{"custom_id": "request-1", "params": {"model": "claude-sonnet-4-6", "max_tokens": 100, "messages": [{"role": "user", "content": "Přejmenuj tuto funkci"}]}}
{"custom_id": "request-2", "params": {"model": "claude-sonnet-4-6", "max_tokens": 100, "messages": [{"role": "user", "content": "Přidej komentáře"}]}}
EOF

# Odešlete batch
curl https://api.anthropic.com/v1/messages/batches \
  -X POST \
  -H "x-api-key: $ANTHROPIC_API_KEY" \
  -F "requests=@batch.jsonl"

# Výsledky dostanete přes GET /v1/messages/batches/{id}
# Typická doba zpracování: 15 minut až 24 hodin

3. Chytrý výběr modelu — ušetřete 3–5×

Největší chyba, které se vývojáři dopouštějí: používají Opus na vše. Opus je výjimečný model — ale pro 80 % každodenní práce je Sonnet stejně dobrý a třikrát levnější. A pro jednoduché opakující se operace je Haiku pětkrát levnější než Sonnet.

# V průběhu session

{ "model": "claude-sonnet-4-6" }

4. Extended Thinking — kdy vypnout

Extended thinking dává Claudovi prostor k hlubší úvaze před odpovědí. Je zapnuto výchozě a "thinking tokeny" se účtují jako output tokeny — tedy $25/MTok na Opus 4.7. To je největší skrytý náklad, o kterém spousta vývojářů neví.

Na jednoduchých úkolech (přejmenování, formátování, přidání komentářů) thinking nepřidává žádnou hodnotu — ale stojí vás desítky procent extra. Nastavte strop nebo ho selektivně vypněte:

Ovládání thinking tokenů
# Globální strop v ENV — doporučeno pro každodenní práci
export MAX_THINKING_TOKENS=8000

# V session — přepínání úrovně přemýšlení
/effort low     -- minimum thinking, rychlé odpovědi
/effort medium  -- výchozí vyvážení
/effort high    -- maximum — jen pro skutečně složité úkoly

# Vypnutí pro celou session
/config thinking: false

5. Session hygiena — kontext a tokeny

Každá zpráva v session, každý přečtený soubor a každý výsledek spuštěného příkazu se přidá do "okna kontextu" — a celé toto okno se posílá s každým dalším requestem. Čím déle session trvá a čím více souborů Claude načte, tím dražší každý další prompt je.

Praktická pravidla pro kontextovou hygienu:

  • Používejte /clear mezi nesouvisejícími úkoly. Přechod z opravy bugu k psaní testů pro jiný modul? /clear uvolní kontext a ušetří tokeny na každém dalším promptu.
  • Nezačínejte den pokračováním včerejší session. Stará session má akumulovaný kontext — raději otevřete novou a přidejte jen to, co je relevantní.
  • Buďte specifičtí o souborech. Místo "podívej se na projekt" napište "přečti src/auth/login.ts". Claude nenačte zbytečné soubory.
  • Vymazávejte velké output bloky. Výsledky spuštěných testů (tisíce řádků) zbytečně zvětšují kontext — pokud jste je přečetli, /clear a pokračujte.
Vliv session hygieny na náklady — praktický příklad
Session s 50 prompty, bez /clear, kontext roste na 300 000 tok~$0.90 na input
Stejná práce, 5 čistých sessions × 10 promptů, kontext ~60 000 tok~$0.18 na input
Úspora 80 % — jen lepší organizací sessionsbez ztráty výsledku

6. Kvalitní CLAUDE.md snižuje počet potřebných promptů

Dobré CLAUDE.md znamená, že Claude hned ví co dělat — nemusí se ptát na konvence, architekturu nebo příkazy. Každý "ujasňovací" prompt navíc stojí tokeny. Investice do dobrého CLAUDE.md se vrátí desetinásobně.

Konkrétně: bez CLAUDE.md strávíte první 2–3 prompty každé session tím, že Claudovi vysvětlujete kontext. S dobrým CLAUDE.md rovnou začínáte pracovat. Při 20 sessions týdně to ušetří 40–60 promptů — v API tokenech klidně $5–15 měsíčně na Opus.

7. Plan mode před drahými operacemi

Plan mode (/plan) nechá Clauda přečíst soubory a navrhnout přístup, aniž by psal kód. Teprve po vašem schválení začne implementovat. Toto zachrání situace, kdy Claude by šel špatnou cestou a vy byste platili za velký refaktoring, který pak zahodíte.
