DÍL 08

Zálohy & Recovery

Agenti a rozsáhlé automatizované změny jsou mocné nástroje — a právě proto vyžadují záchrannou síť. Tento díl vás naučí, jak se chránit, než něco pustíte.

Proč zálohovat — i když používáte Git

Možná si říkáte: mám Git, co se mi může stát? Odpověď je víc, než byste čekali. Git vás ochrání před ztrátou commitnutého kódu — ale ne před všemi scénáři, ke kterým při práci s AI agenty dochází.

Problematické situace, ke kterým dochází v praxi:

  • Agent smaže soubory, které nikdy nebyly commitnuty — nové soubory vytvořené v session, experimentální konfigurace, lokální skripty.
  • Agent přepíše databázová data — pokud má přístup k lokální databázi a provede migraci špatným směrem.
  • Stash se smaže — git stash je místní a dočasný; agent může spustit git stash drop.
  • Agent pushne do remote větve — pokud to není zablokované v deny pravidlech, remote změny jsou viditelné ostatním.
  • Velký refaktoring rozbije testy — a agent "opraví" testy tím, že je smaže místo opravy kódu.
Nejčastější ztráta: uncommitted soubory

Průzkum komunity z roku 2025 ukázal, že 73 % nechtěných ztrát při práci s AI agenty se týkalo souborů, které nikdy nebyly commitnuty do Gitu. Git vám nepomůže, pokud jste zapomněli přidat soubor do repozitáře.

Git jako záchranná síť — správné použití

Git je nejlepší záchranná síť — pokud ho správně používáte. Klíčový princip: commitujte před každou session, kde plánujete větší změny.

Zlaté pravidlo před každou Claude session

Povinný ritual před spuštěním agenta
# 1. Zkontrolujte stav — co je necommitnuté?
git status

# 2. Commitněte vše, co nechcete ztratit
git add -A
git commit -m "WIP: záloha před Claude session $(date +%Y%m%d-%H%M)"

# 3. Vytvořte novou větev pro změny agenta
git checkout -b claude/$(date +%Y%m%d)-popis-ukolu

# 4. Teď teprve spusťte Claude Code
claude

Proč nová větev pro každý větší úkol?

Pokud agent udělá něco špatně, stačí větev smazat a jste zpět na výchozím stavu. Bez nové větve musíte revertovat commity nebo používat git reflog — což je stresující a chybové.

Checkpointy během dlouhé session

Při delší agentic session (více hodin, rozsáhlý refaktoring) je dobré pravidelně vytvářet checkpointy. Claude Code v Desktop App to umí semi-automaticky — po každé dokončené fázi nabídne možnost commitu.

V CLI to uděláte ručně:

Manuální checkpoint v průběhu session
# Pozastavte Claude (Ctrl+C nebo nechte dokončit krok)
# Pak v novém terminálu:

git add -A
git commit -m "checkpoint: po dokončení auth modulu"

# Nebo automaticky každých N minut přes cron / watch:
watch -n 300 'git add -A && git commit -m "auto-checkpoint $(date)"'

Před velkou změnou — komplexní postup

Chystáte se na rozsáhlou migraci, refaktoring celé vrstvy nebo přechod na nový framework? Tady je kompletní postup:

1

Záloha celého projektu mimo Git

Zkopírujte celý adresář projektu na jiné místo. Jednoduché, ale zachrání vás i při smazání .git adresáře.

2

Commitněte aktuální stav

Udělejte commit s jasnou zprávou jako "BEFORE: migrace na PostgreSQL". Tento commit bude váš záchytný bod.

3

Vytvořte novou větev

Pojmenujte ji popisně: claude/postgres-migration-2026-05. Veškerá práce agenta jde do této větve.

4

Záloha databáze (pokud relevantní)

Před jakýmikoli databázovými operacemi: pg_dump, mysqldump nebo snapshot v cloudové konzoli.

5

Spusťte agenta v Plan mode

Před skutečnými změnami nechte Clauda vysvětlit plán. Zkontrolujte ho — hledejte destruktivní operace.

6

Schvalte a sledujte

Nechte agenta pracovat, ale neklikejte "approve all" slepě. Prohlédněte diffy před každým zápisem.

Obnova po chybě agenta — krok za krokem

Stalo se. Agent udělal něco špatně. Nepanikujte — záchrana je téměř vždy možná.

Scénář A: Agent zkazil commitnutý kód

Návrat k poslednímu dobrému stavu
# Zobrazit historii commitů
git log --oneline -20

# Vrátit se k poslednímu dobrému commitu (zachová změny jako unstaged)
git reset --mixed HEAD~3   # vrátí 3 commity zpět

# NEBO: tvrdý reset — zahodí vše od daného commitu
git reset --hard abc1234   # nahraďte hash dobrého commitu

# NEBO: bezpečný revert — vytvoří nový commit "undo"
git revert HEAD~2..HEAD    # revertuje poslední 2 commity

Scénář B: Agent smazal soubory, které nebyly commitnuté

Záchrana přes git reflog
# Reflog zaznamená VŠECHNY pohyby HEAD — i před-commitové
git reflog

# Uvidíte výpis jako:
# abc1234 HEAD@{0}: commit: Claude session změny
# def5678 HEAD@{1}: checkout: přesun na claude/feature
# ghi9012 HEAD@{2}: commit: WIP záloha před session  <-- TADY

# Obnovte stav z reflogu
git checkout ghi9012 -- .   # obnoví všechny soubory z daného stavu

Scénář C: Agent provedl nežádoucí git push

Stažení nežádoucího pushe z remote
# Zobrazit historii remote větve
git log origin/feature-branch --oneline

# Force push zpět na dobrý stav (pozor: přepíše remote historii)
git push origin feature-branch --force-with-lease

# --force-with-lease je bezpečnější než --force:
# selže, pokud mezitím někdo jiný pushoval
Git reflog — váš tajný záchranář

Git reflog uchovává historii na 90 dní ve výchozím nastavení. I když smažete větev, resetujete HEAD nebo přepíšete commity, reflog vám umožní se vrátit. Je to jedna z nejdůležitějších Git funkcí, o které většina vývojářů neví.
