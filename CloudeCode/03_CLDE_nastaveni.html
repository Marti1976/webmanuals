DÍL 03 / 11

Nastavení

CLAUDE.md, settings.json, ENV proměnné a oprávnění nástrojů. Správná konfigurace Claude Code je základ — šetří tokeny, zvyšuje přesnost a chrání váš projekt.

Struktura konfiguračních souborů

Claude Code používá dva typy konfiguračních souborů — CLAUDE.md pro instrukce a kontext projektu, a settings.json pro technické nastavení chování. Oba existují ve dvou vrstvách: globální (platí pro všechny projekty) a projektové (specifické pro jeden repozitář).

~/.claude/ ← globální konfigurace ├── settings.json ← výchozí nastavení pro vše ├── CLAUDE.md ← globální instrukce (vaše preference) └── projects/ ← session historie a logy váš-projekt/ ← projektová konfigurace ├── CLAUDE.md ← projektové instrukce (nejvyšší priorita) └── .claude/ ├── settings.json ← projektové nastavení (přepíše globální) ├── settings.local.json ← lokální přepisy (do .gitignore!) └── commands/ ← vlastní slash příkazy projektu
Klíčové pravidlo

Projektové soubory vždy přepíší globální. CLAUDE.md v projektu se přidá ke globálnímu (oba se načtou). settings.json v projektu přepíše globální hodnotu pro každý klíč, který definuje.

CLAUDE.md — nejdůležitější soubor projektu

CLAUDE.md je soubor, který Claude Code automaticky přečte při každém spuštění v daném adresáři. Je to vaše "příručka projektu pro Clauda" — popisuje architekturu, konvence, příkazy, pravidla a vše, co Claude musí vědět, aby pracoval správně hned od prvního promptu.

Proč je to tak důležité? Bez CLAUDE.md strávíte první 2–4 prompty každé session vysvětlováním kontextu. S dobrým CLAUDE.md Claude okamžitě ví, jaký framework používáte, jak spustit testy, jaké jsou konvence pojmenování a co nesmí dělat. Každý ušetřený "ujasňovací" prompt = ušetřené tokeny a čas.

Doporučené sekce CLAUDE.md

CLAUDE.md — komplexní vzor pro webový projekt
# Název projektu — krátký popis
E-shop na knihy. Next.js 15, PostgreSQL, Stripe platby.

## Příkazy (sem patří vše co Claude bude spouštět)
- `npm run dev`          — Dev server na portu 3000
- `npm run build`        — Produkční build (ověřuje TS typy)
- `npm run test`         — Jest unit testy
- `npm run test:e2e`     — Playwright E2E testy
- `npm run lint`         — ESLint + Prettier
- `npm run db:migrate`   — Spustí čekající migrace (Drizzle ORM)
- `npm run db:studio`    — Otevře Drizzle Studio (DB prohlížeč)

## Architektura
- Next.js 15 s App Router (ne Pages Router)
- Server Components jsou výchozí; `"use client"` jen kdy nutno
- DB přístup výhradně přes Drizzle ORM v server components
- Autentizace: Clerk (ne NextAuth)
- Styly: Tailwind v4 + shadcn/ui komponenty
- API routes v: `src/app/api/`
- Typy v: `src/types/`
- Server akce v: `src/actions/`

## Kódové konvence
- TypeScript strict mode — žádné `any` typy
- Pojmenování souborů: kebab-case (user-profile.tsx)
- Pojmenování komponent: PascalCase (UserProfile)
- Commit messages: imperativ, česky, max 72 znaků
  Příklad: "Přidej validaci emailového formuláře"
- Komentáře v kódu: česky
- Žádné console.log v commitu (jen přes logger util)

## Pravidla pro Clauda
- Nikdy nepushovat přímo do větve `main`
- Vždy spustit `npm run lint` před navrhovaným commitem
- Při změně DB schématu vždy generuj migraci: `npm run db:generate`
- Neměnit soubory v `src/generated/` — generované automaticky
- Při nejistotě o přístupu se zeptej, neimplementuj "nejlepší odhad"

## Prostředí
- `.env.local` pro lokální dev (není v Gitu)
- `.env.example` ukazuje požadované proměnné
- Produkční secrets jsou v Vercel Dashboard

Tipy pro psaní efektivního CLAUDE.md

  • Sekce Příkazy je priorita číslo jedna. Claude bude spouštět příkazy při každé session — pokud nezná správný příkaz pro testy, buď se zeptá (= zbytečný prompt), nebo odhadne špatně. Uveďte všechny relevantní skripty.
  • Pište co Claude dělat nemá. "Neměnit generované soubory", "nepushovat do main", "nezrušit existující migraci" — negativní instrukce jsou stejně důležité jako pozitivní.
  • Commity do repozitáře. CLAUDE.md commitnutý do Gitu sdílí kontext s celým týmem. Každý vývojář má automaticky stejná pravidla.
  • V monorepu jeden CLAUDE.md na každý balíček. Claude načítá CLAUDE.md hierarchicky — kořenový + balíčkový. Každý balíček může mít vlastní konvence.
  • Nepřeplňte ho. CLAUDE.md se čte při každém spuštění — každý token navíc stojí peníze. Pište stručně, bez zbytečných vysvětlení "proč".
Rychlý start — nechte Clauda napsat CLAUDE.md za vás

Spusťte Claude Code v novém projektu a napište: "Prozkoumej projekt a vytvoř CLAUDE.md se všemi releventními informacemi — příkazy z package.json, architekturu z adresářové struktury, konvence z existujícího kódu." Pak ho zkontrolujte a doplňte pravidla specifická pro váš tým.

settings.json — technická konfigurace

settings.json řídí chování Claude Code jako nástroje — výchozí model, oprávnění příkazů, prostředí sessions a MCP servery. Globální soubor je v ~/.claude/settings.json, projektový v .claude/settings.json.

.claude/settings.json — kompletní příklad
{
  // Výchozí model pro session
  "model": "claude-sonnet-4-6",

  // ENV proměnné dostupné v session
  "env": {
    "MAX_THINKING_TOKENS": "8000",
    "NODE_ENV": "development",
    "DATABASE_URL": "postgresql://localhost/myapp_dev"
  },

  // Oprávnění příkazů
  "permissions": {
    "allow": [
      "Bash(npm run test)",
      "Bash(npm run test:*)",
      "Bash(npm run lint)",
      "Bash(npm run build)",
      "Bash(git status)",
      "Bash(git diff)",
      "Bash(git log --oneline -20)",
      "Bash(git add -p)"
    ],
    "deny": [
      "Bash(git push origin main)",
      "Bash(git push --force*)",
      "Bash(rm -rf*)",
      "Bash(sudo*)",
      "Bash(npm publish*)",
      "Bash(DROP TABLE*)"
    ]
  },

  // MCP servery (viz díl 05)
  "mcpServers": {
    "github": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-github"],
      "env": { "GITHUB_TOKEN": "ghp_..." }
    }
  }
}

Allow vs Deny — jak fungují oprávnění

Systém oprávnění pracuje na principu: vše, co Claude navrhne spustit, se buď automaticky schválí (allow), automaticky zablokuje (deny), nebo vyžaduje vaše ruční potvrzení (výchozí).

  • allow — příkazy bezpečné pro automatické schválení. Sem patří testování, linting, čtení stavu Gitu. Claude je spustí bez potvrzení, což urychluje práci.
  • deny — příkazy, které Claude nesmí ani navrhnout. Destruktivní operace, push do main, sudo. Tvrdá pojistka, která platí vždy.
  • Wildcards — hvězdička matchuje cokoli za ní. Bash(npm run test:*) povolí všechny varianty test příkazů.
  • Výchozí — vše ostatní vyžaduje ruční potvrzení ve formě [y/n] v terminálu.
Nikdy do allow

Do allow nepatří: git push, rm, sudo, příkazy měnící produkční data, npm publish. Tato pravidla neexistují pro pohodlí, ale jako záchranná síť před chybou agenta.

Proměnné prostředí

ENV proměnné lze nastavit třemi způsoby — v shellu (pro přihlašení), v settings.json (pro session kontext) nebo přes export v shellu před spuštěním Claude.

Klíčové ENV proměnné · ~/.zshrc nebo ~/.bashrc
## Autentizace (alternativa k claude auth login)
export ANTHROPIC_API_KEY="sk-ant-api03-..."

## Omezení thinking tokenů — výchozí je neomezeno!
export MAX_THINKING_TOKENS=8000

## Výchozí model (přepíše settings.json)
export ANTHROPIC_MODEL="claude-sonnet-4-6"

## Windows — cesta ke Git Bash (pokud není v PATH)
export CLAUDE_CODE_GIT_BASH_PATH="/c/Program Files/Git/bin/bash.exe"

## Disable auto-update (pokud používáte verzi pin v CI)
export CLAUDE_CODE_DISABLE_AUTO_UPDATE=1

## Logování na verbose úroveň (pro debugging)
export CLAUDE_CODE_LOG_LEVEL="debug"

Výběr výchozího modelu

Model nastavený v settings.json nebo ENV proměnné je výchozí pro všechny sessions, dokud ho nepřepíšete. Doporučení: Sonnet 4.6 jako výchozí — je výkonný pro 80 % úkolů a 3× levnější než Opus. Opus si nechte pro explicitní spuštění na náročné úkoly.

Nastavení výchozího modelu
## V settings.json
{ "model": "claude-sonnet-4-6" }

## Přepsání pro konkrétní session
claude --model claude-opus-4-7

## Přepnutí modelu uprostřed session
/model claude-haiku-4-5

## Dostupné modely (stav: květen 2026)
claude-opus-4-7        — nejsilnější, nejdražší ($5/$25 /MTok)
claude-opus-4-6        — stabilní alternativa k 4.7
claude-sonnet-4-6      — výchozí, nejlepší poměr výkon/cena
claude-haiku-4-5       — nejrychlejší, nejlevnější ($1/$5 /MTok)

Hierarchie priorit — přehled

Když Claude Code načítá konfiguraci, aplikuje ji v tomto pořadí (vyšší číslo = vyšší priorita, přepíše nižší):

  • 1. Globální settings ~/.claude/settings.json — vaše osobní výchozí nastavení
  • 2. Globální CLAUDE.md ~/.claude/CLAUDE.md — vaše osobní instrukce (styl, preference)
  • 3. Projektové settings .claude/settings.json — nastavení konkrétního projektu
  • 4. Projektové CLAUDE.md CLAUDE.md v kořeni projektu — instrukce projektu
  • 5. Lokální přepisy .claude/settings.local.json — vaše osobní lokální odchylky (nepushovat!)
  • 6. CLI přepínače — --model, --auto-approve atd. — přepíší vše ostatní
Doporučení pro týmy

Commitujte do repozitáře: CLAUDE.md a .claude/settings.json. Do .gitignore přidejte: .claude/settings.local.json. Tím každý vývojář sdílí projektová pravidla, ale může si lokálně přepsat třeba výchozí model nebo výchozí oprávnění.
