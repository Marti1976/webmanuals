Limity & Efektivita

Jak se spalují tokeny?

Tokeny nejsou rovnoměrně drahé. Každá operace — čtení, psaní, paměť, cache, model — má svou cenu. Zde je matice:

OperaceCenaKdy se stane?
Vstup (input token)Základní sazbaKaždá vaše zpráva, soubory, kontext, paměť, instrukce
Výstup (output token)2× vstupOdpověď Claudea, jakákoli generovaná délka
Cache reads0,1× vstupKdyž přečte znovu stejný obsah ze cache
Cache writes1,25× vstupKdyž poprvé vloží soubor do cache (jednou)
Paměť (Memory)0,5× vstupAutomatické shrnutí cross-session (jednou za session)
Batching0,05-0,5× vstupPouze v Batch API s povoleným discountem
Prakticky

Pokud pošleš stejný 100KB soubor 10×: Poprvé = 125 tokenů (cache write), pak 9× po 10 tokenech (cache read) = 125 + 90 = 215 tokenů za vše. Bez cache = každý přečet plný cena.

Čtyři klíčové opravy pro tokeny

1. Paměť (Memory) není "paní všehochuť"

Memory neuchovává konverzaci — uchovává shrnutí klíčových faktů a předává je dalším session. Cena: poprvé 1 soubor sumarizace, pak 0,5× vstup (automaticky).

  • Co ukládat: Styl psaní, preferované nástroje, kontakt na lidi, pravidelné projekty, osobní pravidla.
  • Co NEUKLÁDAT: Faktů, která se mění (ceny, aktuální novinky), šetří to jen čas, ne tokeny.
  • Doba: Memory se aktualizuje jednou za session, ne každou zprávu.

2. Cache — nejlevnější opakování

Vložíš-li stejný PDF 5× do jedné session, cache se aktivuje po druhém používání. Výstupní sazby klesnou na 10% ceny vstupu.

  • Paměť cache: 5 minut až 1 hodina (v závislosti na účtu, předplatném).
  • Co ji ruší: Výměna modelů, změna úsilí, příkaz /compact, přepnutí Fast, připojení MCP.
  • Bez cache: Dlouhé pauzy (nad 1 hodinu) = studený start, vše se znovu čte za plnou cenu.

3. Batching — až 50% úspora na masivním provozu

Máš-li stovky zpráv, které je možné spustit bez čekání, Batch API je 10× levnější než live. Vyplatí se jen pro automatizaci nocí.

Příklad: Refaktoring 1000 souborů

Live API: 1000 × plná cena = 500 USD
Batch API: 1000 × 50% cena = 250 USD (asynchronní, do rána)
Úspora: 250 USD a žádné limity live session

4. Volba modelu — nejdůležitější rozhodnutí

Ne všechno potřebuje Opus. Výběr správného modelu = až 80% úspora.

  • Haiku: Rutina, extracty, formatování — 80% levnější než Opus.
  • Sonnet: Vyvažuje cenu a kvalitu — 50% levnější než Opus, kvalita na 95%.
  • Opus: Složitá architektura, debugging, design. Jen pro klíčové session.

Master Prompt — single source of truth

Master Prompt = jediný text, který se Loading v každé session. Šetří to opakované psaní instrukcí a zabrání chybám.

Příklad master promptu
Vy jste expert na Python, s 15 let zkušenosti v backend development.

Vaše role:
- Psát čitatelný, dokumentovaný kód
- Nikdy nepiš bez type hints
- Vždy napřed vrácíš plán, pak kód

Výstupní formát:
1. PLÁN — Jak to vyřeším (text, ne kód)
2. KÓD — Implementace + komentáře
3. VERIFIKACE — Jak si ověřit, že funguje

Nikdy neměň tyto pravidla.

Jakmile Master Prompt nastavíš, do druhé session se už nemusíš opakovat — Claude si jej pamatuje.

Pět návyků — jak přestat cpát tokeny

Návyk 1: Jedna zpráva = jedna myšlenka

Špatně: "Kontrola textu A, pak B, pak vytvořit C" — 3 úkoly = 3 přepsání kontextu = potřeba 3 session.

Dobře: Rozděl do 3 zpráv: (1) A, (2) B, (3) C. Každá si vezme kontext z předchozí bez přepisování.

Návyk 2: Vkládej soubory jednou, ptej se mnohokrát

PDF jednou do cache → pět otázek k témuž PDF = 1× cache write + 4× cache read (80% úspora).

Návyk 3: Ne ke každému souboru komentář

Když vkládáš 50 drobných souborů, nespiš "tady je soubor A, tady je B..." — to jsou zbytečné tokeny. Prostě je vlož, Claude je vidí sám.

Návyk 4: Prompt jednou, varianty později

Dobrý prompt = 50% úspora. Uprav prompt jednou, pak jej kouš-kouš vylepšuj v další session, ne chaoticky.

Návyk 5: Archivuj session bez obsahu

Session která bude stále otevřená = neurčitá cache doba. Archivuj ji — nová session = čistý start, bez legacy kontextu.

Žebříček krok za krokem

  • Zůstáváte v Claude: Hlavní session Opus. Haiku v skills/pod-agentech. Sonnet pro rutinu. Fable pro design. Nula přepnutí uprostřed session.
  • Kdy odejít na Codex: Exekuce náročná na tokeny, kde je plán hotový. Claude = ověřování, Codex = rychlý výstup. Až 4× méně tokenů. Dvě předplatná = dva rozpočty.
  • Kdy odejít na DeepSeek/GLM: Objemná práce s nízkým rizikem — masivní refaktoring, batch, noční běhy. Kapacita na token > kvalita.

Dlouhé pauzy a cache — kritické!

Pokud si dáte delší pauzu u session s 200k kontextem, cache vyprší dříve než se vrátíte. Cache je časovač, ne uložený soubor — cca 1 hodina u předplatného. Když si berete delší pauzu, /clear před odchodem — cache kterou se snažíte chránit stejně vyprší dříve, než se vrátíte.

Mýty a jejich pravdy

❌ Mýtus

/compact šetří tokeny

✓ Pravda

/compact znovu odešle celou konverzaci aby ji sumarizoval (nejrozdávanější zpráva) a pak smaže cache. Kontinuita bez úspory.

❌ Mýtus

Pište kratší prompty

✓ Pravda

Vaše psaní = ~0,01 % účtu. Vágní prompty stojí kvůli předělávání, ne délce.

❌ Mýtus

Pod-agenti šetří tokeny

✓ Pravda

Tokeny se přesouvají. Každý pod-agent má svůj systém prompt, paměť, nástroje. Vyplatí se jen u dlouhých session.

❌ Mýtus

Obrázek s textem šetří tokeny

✓ Pravda

Obrázek není levnější. A model v obrázku nemůže editovat. Vždy text.

  • Soubory v cache navždy? Ne — cache trvá 5 minut až 1 hodina. Dlouhé pauzy = opakované zpracování za plnou cenu.
  • Claude Code v pozadí čerpá limity? Ne — nečinný běh stojí <4 centy. Skutečný únik je v úlohách a týmech agentů.

Ruční nastavení — 60 vteřin práce

Tři věci která se dělají jednou a pak fungují automaticky:

  • Odpojte nepoužívané konektory: V aplikaci: Nastavení → Konektory. Nebo CLI: claude mcp remove <název>
  • Nastavte úsilí na začátku: Platí stejné pravidlo cache. Zvolte jednou, neměňte.
  • Zapněte statusline: Master Prompt ji nastaví. Živý ukazatel nákladů změní vaše chování více než jakékoli pravidlo.

Bonusová sekce: Designérská práce — kde tokeny mizí nejrychleji

Designové session jsou nejdražší — zpětná vazba funguje na snímcích a přepisování souborů. Jeden snímek = ~2 700 tokenů. 4K = ~5 000. 30 iterací se snímky = 100k+ tokenů jen v pixelech.

  • Kodifikujte vkus jedorázově: Design style guide jednou — paleta, typografie, mezery, ~2 KB. Každá další session jej načte.
  • Reference → specifikace: Máte web? Extrahujte do souboru. Dále předávejte specifikaci, ne referenci.
  • Kritici s čistým kontextem: Pod-agenti posoudí vzhled ve svém kontextu, vrátí verdikty jako text (levné).
  • Text před pixely: Nejdříve DOM a CSS. Snímek až když text nestačí.
