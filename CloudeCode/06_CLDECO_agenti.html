DÍL 06

Agenti

Co jsou agenti, jak je konfigurovat a kdy je použít. Subagenti, paralelní zpracování, Agent Teams pro orchestraci a Cloud Routines pro automatizaci.

Co jsou agenti a jak fungují

Agent je režim, ve kterém Claude Code pracuje autonomně — sám spouští příkazy, čte výstupy, upravuje kód a vrací se k úkolu, dokud ho nedokončí. Není to chatbot, který čeká na váš vstup po každém kroku.

Klasická interactive session: "Oprav ten bug" → Claude se ptá → vy odpovídáte → Claude dělá krok 1 → ptá se znovu … Agentic mode: "Oprav ten bug" → Claude sám prochází debuggingem, vrací se s reportem, konec.

V praxi to znamená, že můžete agentu dát rozsáhlý úkol (refaktoring, generování testů, hromadná oprava) a on práci dokončí bez vašeho zásahu — pokud operace spadají do kategorie "schválených" (allow list ze settings.json).

Terminologie v dokumentaci

Anthropic používá termíny agentic loop (smyčka), tool use (volání nástrojů), orchestrator (hlavní agent koordinující ostatní) a subagent (agent provádějící konkrétní podúkol). V Claude Code se s tím setkáte v logování a při debugování.

Kdy se agent aktivuje automaticky

Claude Code přechází do agentic mode automaticky, pokud mu dáte úkol, který vyžaduje více kroků — například "přidej autentizaci do aplikace" nebo "oprav všechny failing testy." Indikací je, že Claude začne sám spouštět příkazy bez toho, aby se vás ptal na každý krok.

Pokud chcete explicitně spustit agenta na delší autonomní úkol, použijte přepínač --auto-approve nebo povolte auto mode v nastavení:

Spuštění agenta
# Autonomní režim — Claude sám schvaluje bezpečné operace
claude --auto-approve "Přemigruj všechny testy z Jest na Vitest"

# Plan mode nejdřív — Claude navrhne celý plán, pak teprve pusťte agenta
claude --plan "Refaktoruj databázovou vrstvu na Repository pattern"
# → po schválení plánu spusťte agenta na implementaci

Subagenti — delegování podúkolů

Subagent je samostatná instance Clauda spuštěná hlavním agentem (orchestrátorem) pro konkrétní podúkol. Orchestrátor definuje co se má udělat, subagent dostane vlastní kontext a provede práci.

Výhoda je izolace: každý subagent pracuje ve vlastním kontextovém okně, takže hlavní agent nemusí nést v paměti všechny detaily každého podúkolu. To je klíčové pro velké projekty, kde by kontext jinak přetekl.

Příklad: orchestrátor + 3 subagenti

Hlavní prompt pro orchestrátora
Potřebuji připravit novou verzi produktu. Deleguj tyto úkoly:

1. Subagent A: Projdi všechny TODO komentáře v kódu a vyřeš je nebo 
   vytvoř GitHub issues pro ty, které jsou nad rámec tohoto PR
2. Subagent B: Napiš unit testy pro všechny funkce bez test coverage
3. Subagent C: Aktualizuj dokumentaci podle posledních změn v API

Po dokončení mi dej souhrnný report, co každý udělal.
Upozornění k nákladům

Každý subagent spotřebovává tokeny samostatně. Tři paralelní subagenti = trojnásobná spotřeba oproti jednomu agentovi. Na Pro plánu ($20) limity rychle vyčerpají. Subagenty jsou praktické na Max 20× ($200) nebo přes API s rozmyslným nastavením.

Paralelní zpracování

Největší silou agentů je paralelizace — spouštět více nezávislých úkolů současně, ne sequenčně. Místo 3 hodin práce za sebou to může trvat 1 hodinu, pokud úkoly na sobě nezávisí.

Kdy paralelizace dává smysl

  • Nezávislé moduly — Refaktoring frontendu a backendu zároveň (pokud nesdílí rozhraní).
  • Generování testů — Každý subagent píše testy pro jinou část kódu.
  • Hromadná analýza — Review bezpečnosti v různých vrstvách aplikace současně.
  • Jazykové lokalizace — Překlad do více jazyků paralelně.

Kdy paralelizace nedává smysl

  • Závislé kroky — Napsání kódu musí být před psaním testů.
  • Sdílené soubory — Dva agenti upravující stejný soubor způsobí konflikty.
  • Sekvenční migrace — Databázové migrace musí jít v pořadí.
Paralelní spuštění přes Git worktrees
# Vytvoř izolované kopie projektu pro každého agenta
git worktree add ../projekt-agent-a feature/agent-a
git worktree add ../projekt-agent-b feature/agent-b

# Spusť každého agenta v jeho worktree (v separátních terminálech)
# Terminál 1:
cd ../projekt-agent-a && claude "Refaktoruj AuthService na JWT"

# Terminál 2:
cd ../projekt-agent-b && claude "Napiš E2E testy pro checkout flow"

# Po dokončení merge přes standardní PR review

Agent Teams

Agent Teams je pokročilejší orchestrace dostupná v Desktop App od dubna 2026. Namísto ručního spuštění worktrees se celý tým agentů konfiguruje a monitoruje přes GUI.

V rozhraní vidíte všechny aktivní agenty jako "karty" — každá ukazuje aktuální krok, spotřebu tokenů a stav. Můžete agenta pozastavit, upravit instrukce za běhu nebo ho úplně zastavit bez nutnosti přepínat terminály.

Jak nakonfigurovat Agent Team

  • Otevřete Desktop App → New Team Session.
  • Definujte orchestrátora — popište celkový cíl a přiložte context soubory.
  • Přidejte agenty — každý dostane název, instrukce a přiřazený worktree nebo adresář.
  • Nastavte závislosti — agent B začne až po dokončení agenta A (pokud je to potřeba).
  • Spusťte a sledujte progress v reálném čase.

Cloud Routines — automatické spouštění

Cloud Routines umožňují spouštět Claude Code agenty automaticky bez vašeho zásahu — na základě časového plánu (CRON), webhooku nebo jiné události. Jde v podstatě o "crontab" pro AI agenty.

Jak Routines fungují

Routine je definovaná v Anthropic Console nebo přes API. Obsahuje: trigger (kdy spustit), instrukce pro agenta (co udělat), oprávnění (k jakým nástrojům a repozitářům má přístup) a notifikace (kam poslat výsledek).

Příklad Routine via API — každý den v 6:00
POST https://api.anthropic.com/v1/routines

{
  "name": "daily-security-scan",
  "schedule": "0 6 * * *",
  // spustí se každý den v 6:00
  "instructions": "Prohledej kód pro nové bezpečnostní zranitelnosti. Zkontroluj závislosti (npm audit). Vytvoř GitHub issue pro každý nalezený problém s prioritou High nebo Critical.",
  "repository": "github.com/moje-org/muj-projekt",
  "notify": {
    "slack_channel": "#security-alerts"
  }
}

Praktické use cases pro Routines

  • Denní security scan — Kontrola závislostí a kódu pro zranitelnosti každé ráno.
  • Aktualizace dokumentace — Po každém mergi do main automaticky aktualizuj README a API docs.
  • Monitoring dead code — Každý týden najdi nepoužívané funkce a vytvoř cleanup issues.
  • Zpráva o stavu projektu — Každý pátek pošli přehled otevřených TODO, failing testů a tech debt do Slacku.
  • Dependency updates — Každé pondělí vytvoř PR s aktualizacemi závislostí (a rovnou otestuje, jestli build prochází).
Praktický tip

Začněte s Routines na bezpečných, read-only úkolech — jako jsou analýzy nebo příprava reportů. Teprve až budete důvěřovat chování agenta, přidejte oprávnění pro zápis a vytváření PR. Vždy nastavte notifikaci o výsledku.

Monitoring a řízení nákladů agentů

Agentní úlohy mohou spotřebovat překvapivě mnoho tokenů, protože každý krok v agentic smyčce znovu posílá celý kontext. Jedna tisícistránková refaktorizace může stát desítky dolarů v API tokenech.

Jak sledovat spotřebu

Sledování nákladů v session
# V průběhu session
/stats       -- Pro/Max: zobrazí využití vůči limitu
/cost        -- API uživatelé: přesná cena v USD za session

# Po skončení session — záznam v logu
# macOS/Linux:
cat ~/.claude/logs/session-$(date +%Y%m%d).json | grep total_tokens

# Nástroj cc-usage pro historický přehled
npx cc-usage

Limity pro agenty — jak nastavit strop

.claude/settings.json — limity pro agentic runs
{
  "agentLimits": {
    // Maximální počet kroků v jedné agentic smyčce
    "maxSteps": 50,
    // Strop tokenů na jednu agentic session (API billing)
    "maxTokensPerSession": 500000,
    // Zastavit a zeptat se uživatele při nejistotě
    "confirmOnUncertain": true
  }
}
