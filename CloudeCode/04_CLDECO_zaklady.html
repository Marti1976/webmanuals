Základy

Od prvního spuštění přes slash příkazy až po kompletní workflow — commit, PR, testy. Vše přirozeným jazykem, plus tipy jak psát prompty aby Claude pracoval přesně jak chcete.

Spuštění první session

Terminal — první spuštění
# Přejděte do projektu
cd ~/projekty/muj-web

# Spusťte Claude Code
claude

# Claude přečte strukturu projektu a CLAUDE.md
✓ Načteno 47 souborů · Git větev: main · Sonnet 4.6
✓ Přečteno CLAUDE.md (320 tokenů)

# Prompt — zadejte úkol přirozenou češtinou
> Přidej validaci emailového formuláře v ContactForm.tsx

Co se děje pod kapotou — jak Claude pracuje

Než zadáte první prompt, je dobré vědět, jak Claude Code funguje. Není to chatbot, který píše kód do odpovědi — je to agent, který skutečně čte soubory, spouští příkazy a zapisuje změny na disk.

Při každém promptu Claude projde tímto cyklem:

1

Čtení kontextu

Claude si přečte CLAUDE.md, prozkoumá strukturu projektu a načte relevantní soubory. Vidíte řádky jako "Reading src/auth/login.ts..." — to je Claude, jak se orientuje v kódu.

2

Analýza a plánování

Claude pochopí zadání, identifikuje které soubory musí změnit a jakým způsobem. Pokud si není jistý přístupem, může se zeptat nebo navrhnout plán (v Plan mode).

3

Navrhuje změny — zobrazí diff

Před zápisem Claude ukáže přesný diff každého souboru, který chce změnit. Máte možnost schválit celou sadu, nebo zamítnout konkrétní soubor a vysvětlit proč.

4

Zapíše soubory

Po vašem schválení Claude zapíše změny na disk. Toto je nevratné (bez Gitu) — proto je dobré mít commitnutý stav před každou velkou session.

5

Ověření (testy, lint)

Claude automaticky nabídne spuštění testů a lintu. Pokud testy selžou, Claude analyzuje chybu a navrhne opravu — a může celý cyklus opakovat.

One-shot příkazy — bez interaktivního REPL

Příznak -p ("print") spustí Claude, provede jeden úkol a vrátí výstup do stdout. Claude se ukončí — nečeká na další vstup. Skvělé pro scripting, CI/CD a rychlé jednorázové dotazy z terminálu.

One-shot příklady
# Vysvětlení funkce
claude -p "Vysvětli mi funkci parseConfig v src/config.ts"

# Generování testů pro soubor
claude -p "Napiš unit testy pro src/utils/validators.ts"

# Pipe — Claude čte stdin
cat error.log | claude -p "Co způsobuje tuto chybu a jak ji opravit?"

# Commit message z git diff
git diff --staged | claude -p "Napiš commit message v češtině, imperativ, max 72 znaků"

# Výstup jako JSON (pro scripting)
claude -p "Popiš API endpointy v src/api/ jako JSON pole" --output-format json

# Tichý režim — jen výsledek, žádné UI
claude -p "Počet TODO komentářů v src/" --silent

Plan mode vs Auto mode

Plan mode — nejdřív plán, pak kód

Plan mode aktivujete příkazem /plan nebo příznakem --plan. Claude přečte relevantní soubory, navrhne strukturovaný plán co přesně udělá (které soubory změní, jak) — a čeká na vaše schválení. Teprve po odsouhlasení začne psát kód.

Proč to dělat? Pokud Claude začne špatnou cestou, opravit plán stojí zlomek tokenů oproti zahozenému kódu z celé implementace. Plan mode je obzvlášť cenný pro úkoly, kde si nejste jistí přístupem nebo kde existuje víc způsobů řešení.

Aktivace Plan mode
# Slash příkaz v session
/plan Refaktoruj AuthService na stateless JWT autentizaci

# Příznak při spuštění
claude --plan "Přemigruj databázi z MySQL na PostgreSQL"

# Claude odpoví plánem jako:
Plán změn:
1. Aktualizuji src/auth/auth.service.ts — přidám JWT signování
2. Upravím src/auth/auth.middleware.ts — ověřování tokenu
3. Odstraním session tabulku z databázového schématu
4. Aktualizuji testy v src/auth/__tests__/
Pokračovat? [y/n]

Auto mode — autonomní práce s guardrails

Auto mode (--auto-approve) povolí Claudovi provádět operace ze schváleného allowlistu bez potvrzení u každého kroku. Není to totéž jako --dangerously-skip-permissions — guardrails stále platí, jen schvalování bezpečných operací probíhá automaticky. Vhodné pro opakující se, dobře definované úkoly.

Git operace přirozeným jazykem

Claude Code ovládá kompletní Git workflow — nemusíte znát přesnou syntax příkazů. Stačí popsat co chcete.

Příklady Git operací
## Základní operace
> Jaké jsou uncommitted změny a proč jsou tam?
> Commitni všechno s popisem "Přidej validaci emailu"
> Squashni poslední 3 commity do jednoho

## Větve
> Vytvoř větev feature/dark-mode a přesuň mě na ni
> Mergni větev hotfix/login-bug do main
> Smaž všechny větve co jsou už mergnuté

## PR a review
> Vytvoř PR do main — titulkem v angličtině, popis česky
> Shrň změny v tomto PR pro code review

## Záchrana
> Vrať soubor src/auth.ts do stavu před posledním commitem
> Ukaž mi co se změnilo v posledním týdnu v src/

Tipy pro psaní efektivních promptů

  • Specifikujte soubory explicitně. "Oprav validaci v src/forms/ContactForm.tsx" je lepší než "Oprav formulář." Claude nenačítá zbytečné soubory a vaše záměr je jasný.
  • Dejte negativní instrukce. "Neupravuj existující testy, jen přidej nové" nebo "Nepoužívej lodash, máme vlastní util funkce." Bez nich Claude odhaduje.
  • Uveďte příklad nebo vzor. "Podobně jako je to uděláno v UserProfile.tsx" — Claude pochopí konvence z existujícího kódu lépe než z abstraktního popisu.
  • Rozdělte velký úkol na etapy. Místo "Refaktoruj celou databázovou vrstvu" → "Nejdřív mi ukaž plán → po schválení implementuj jen Repository třídy → pak testy → pak migrace."
  • Sdělte proč, ne jen co. "Přidej caching na API calls protože UI laguje při každém refreshi" dá Claudovi kontext pro lepší rozhodování.
  • Zkontrolujte diff před schválením. Vždy aspoň přejetím oka — Claude může změnit i věci, které nezmiňoval. Diff je váš poslední filtr.

Časté začátečnické chyby

  • Spuštění ve špatném adresáři. Claude pracuje v aktuálním adresáři. Pokud spustíte claude v domovském adresáři místo v projektu, přečte jiné soubory a bude zmaten.
  • Příliš vágní prompt. "Oprav to" nebo "Udělej lepší" — bez kontextu Claude buď se zeptá (= zbytečný round-trip) nebo odhadne špatně.
  • Nezálohovat před agentic session. Viz díl 08 — git commit před každou session je pojistka.
  • Neopravit CLAUDE.md po změnách projektu. CLAUDE.md reflektuje stav projektu — pokud přejdete na jiný framework nebo změníte příkazy, aktualizujte ho.
  • Nechávat session běžet příliš dlouho. Kontext narůstá, každý prompt je dražší. /clear je váš přítel.
