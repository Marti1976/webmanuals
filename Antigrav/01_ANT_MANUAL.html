Co je Antigravity 2.0

Antigravity 2.0 bylo oznámeno na Google I/O 2026, 19. května 2026 a představuje radikální přestavbu původního nástroje. Není to update — je to nová kategorie produktu.

ℹ️
Zkrácená definice

Antigravity 2.0 je standalone, agent-first desktop platforma pro macOS, Windows a Linux. Přirozený jazyk je primární programovací rozhraní. Popisuješ co chceš — agenti naplánují architekturu, napíší kód, otestují ho v prohlížeči a nasadí.

Původ jména a produktu

Název není náhodný. Má tři vrstvy:

  • Python Easter Egg: import antigravity v Pythonu 3 otevře XKCD komiks #353 — vtip o tom jak Python dělá nemožné snadným
  • Doslova: Antigravity odstraňuje tíhu boilerplate kódu, debugování a deployment friction z ramen developera
  • Windsurf dědictví: Produkt byl z velké části postaven týmem bývalého Windsurf IDE, který Google získal licenční a talent deal v roce 2025. Windsurf byl pojmenován po sportu, který vzdoruje gravitaci — tematická návaznost je záměrná

Desktop App 2.0 — novinky v detailu

Flagship surface. Standalone aplikace bez závislosti na VS Code nebo jiném editoru. Čtyři zásadní novinky oproti v1:

1. Dynamic Subagents nové

Ve verzi 1.0 Manager Surface zobrazoval jednoho agenta najednou a ostatní spouštěl asynchronně. Ve 2.0 mohou agenti sami dynamicky spawnovat subagenty pro paralelizaci práce.

🔀
Jak to funguje v praxi

Zadáš: "Audit the auth flow across all microservices." Hlavní agent rozdělí práci do stromu subagentů — každý scope na jednu službu, všechny běží souběžně. Výsledky streamují zpět do Manager Surface. V živém demu na I/O 2026 bylo nasazeno 93 AI agentů paralelně za 12 hodin za méně než $1,000 compute — výsledek: funkční operační systém schopný spustit Doom.

2. Scheduled Tasks nové

Background automation má poprvé first-class místo v editoru. Nastavíš cron-like schedule a agent běží bez toho, abys musel mít appku otevřenou.

  • Nightly dependency upgrades — každou noc zkontroluje a navrhne aktualizace
  • Weekly security scans — automatický audit bezpečnostních zranitelností
  • Post-release refactor sweeps — spustí se automaticky po každém release tagu
  • Continuous monitoring — sledování performance regression v CI

3. Native Voice Commands nové

Diktuj kód, ptej se agenta na diff, spusť testy hlasem. Real-time přepis je poháněn Gemini audio modely. Konzistentní s nedávnými voice rollouts v Gmailu a Docs.

🎙️
Live Voice Transcription
Mluv přirozeně, Gemini audio modely přepíší a odešlou jako task agentovi. Bez přepínání kontextu.
🔊
Voice-driven sessions
Celá coding session jen hlasem — "show me the diff", "approve the plan", "run tests". Heavy users s Ultra plánem využijí naplno.

4. Nové integrace nové

🔬
Google AI Studio
Export projektů přímo z AI Studia do lokální instance Antigravity včetně plného kontextu. Žádný context-switch.
📱
Android
Nativní agent loops pro vývoj mobilních aplikací. Build Android appky s agentem který vidí emulátor.
🔥
Firebase
Deploy bez context switch — agent nasadí přímo na Firebase z Antigravity workspace bez extra konfigurace.

Projects a Scoped Permissions

2.0 přechází z repository-centric na project-centric model. Agenti mohou pracovat přes více složek, nástrojů a tasků s jasnými hranicemi.

  • Project-level settings — každý projekt má vlastní konfiguraci agenta
  • Bounded access — agent vidí jen to, co mu projekt dovolí
  • Persistent permission trust — jednou schválené akce si project pamatuje
  • Multiple workspaces — přepínáš mezi projekty bez ztráty kontextu

Co zůstalo z v1.0

Všechny core features původního IDE jsou stále přítomné:

👀

🎛️

📋

Task-level deliverables — plán, diff, screenshot, summary. Vše na jednom místě pro ověření.
🧠
Knowledge Base
Kontextová paměť projektu. Agent čte i zapisuje — self-improvement jako core primitive.
🤖
Čtyři tenets Antigravity
  • Trust — kontext na přirozené task-level abstrakci, artifacts a verification pro důvěru uživatele
  • Autonomy — agenti operují přes všechny surfaces zároveň, uživatel interaguje asynchronně
  • Feedback — intuitivní async feedback (Google-doc-style komentáře, select-and-comment na screenshots)
  • Self-improvement — agent akce přispívají do knowledge base pro kontinuální zlepšení

Antigravity CLI nové v 2.0

Terminálový binary napsaný v Go — rychlejší a responzivnější než předchůdce (Gemini CLI). Stejný agent harness jako desktop app, ale bez GUI.

⚡
Proč Go?

Google zvolil Go pro CLI z důvodu rychlosti startu, nízké memory footprint a jednoduché distribuce jako single binary. Gemini CLI bylo v Node.js — nástupce je výrazně rychlejší.

Instalace CLI

# macOS / Linux — jednopříkazová instalace curl -sSL https://antigravity.google/install.sh | bash # Python SDK (alternativa) pip install google-antigravity # Ověř instalaci antigravity --version

Základní použití

# Spuštění agenta na refaktoring antigravity agent run "refactor the rate-limit middleware" \ --repo ./services/api \ --model gemini-3.5-flash # Agent s více povoleními antigravity agent run "add unit tests to all auth handlers" \ --repo ./src \ --allow shell,code_edit,web_search \ --model gemini-3.5-flash # Naplánovaný task (cron) antigravity schedule add \ --cron "0 3 * * *" \ --task "run security audit and create report" \ --repo ./ # Zobrazit výsledky scheduled runů antigravity schedule results --last 7

CLI vs Claude Code vs ostatní

Antigravity CLI orchestruje více agentů z terminálu a může dispatchovat subagenty. Claude Code je single-agent CLI. To je zásadní rozdíl pro komplexní workflows.

🔧
Napojení na CI/CD pipeline

CLI se dá drátovat přímo do pre-commit hooks, GitHub Actions a pre-deploy gates. V kombinaci s Apidog headless: agentic CI pipeline která píše testy, spouští je na mock serveru a merguje jen při splněných kontraktech.

Antigravity SDK nové v 2.0

SDK zpřístupňuje agent harness programaticky. Definuješ vlastní agent behaviors a hostíš je kdekoliv — vlastní EC2, Vertex AI nebo on-prem.

Definice vlastního agenta

from antigravity import Agent, Tool # Definice backend code reviewer agenta agent = Agent( model="gemini-3.5-flash", tools=[Tool.shell, Tool.code_edit, Tool.web_search], system="You are a backend code reviewer. " "Block any PR that ships SQL without an index.", ) result = agent.run("review PR #421") print(result.artifacts) # List[Artifact] print(result.summary) # str — co agent udělal print(result.approved) # bool — schválit PR?

Gemini optimalizace v SDK

⚡
Nižší latence a náklady s Gemini

SDK je optimalizovaný pro Gemini modely — nižší latence a nižší cena díky cache hits a tool-call optimalizaci. Ostatní providery (Claude, GPT) fungují, ale Gemini dostává výhody. Rozhoduj dle toho, za jakou model family již platíš.

Managed Agents API nové v 2.0

Největší novinka pro API konzumenty. Managed Agents přidává novou endpoint rodinu do Gemini API kde popisuješ cíl, uvádíš povolené nástroje a Google spustí agenta za tebe. Serverless agenti — platíš za runs, Google zajišťuje loop, scaling, retries a tool execution.

Tři úrovně kontroly

🔬
Direct model calls
Spravuješ loop, tools a state sám. Nejlevnější, nejvíce flexibilní, nejvíce kódu.
☁️
Managed Agents
Deklaruješ cíl a tools. Google spravuje loop. Méně kódu, více guardrailů. Pro long-running tasks.
🖥️
Desktop / CLI / SDK
Spouštíš agenta lokálně. Plná kontrola, žádný managed scaling. Pro citlivé workloads mimo VPC.

Kdy použít co

  • Direct calls — high-volume, single-step inference (klasické Gemini volání)
  • Managed Agents — long-running tasks kde spolehlivost > per-call cost
  • SDK/Desktop — citlivé workloads které nesmí opustit tvůj VPC
⚠️
Cena managed agents

Managed Agents tasky mohou trvat minuty. Platíš za celý run, ne jen za jednu inference. Při vývoji frontendu použij Apidog smart mock pro canned "completed" response — živý endpoint zapoj až když UI zvládne async flow.

Enterprise Agent Platform nové v 2.0

Pro organizace na Google Cloud se Antigravity pluguje přímo do Gemini Enterprise Agent Platform. Stejné agent definice se pohybují mezi SDK (developer-hosted) a Enterprise Platform (Google-hosted).

Co Enterprise tier přináší

🔐
SSO přes Google Workspace
Žádné separátní účty. Single sign-on z Workspace, role management přes existující Google groups.
📊
Audit logy každé akce
Každý agent tool call, každá změna souboru, každý shell příkaz je zalogován a exportovatelný.
🏗️
VPC-Service-Controls
Scoping agentních akcí na definované VPC perimetry. Kód neopustí tvou infrastrukturu.
📈
BigQuery analytics
Run analytics — kolik tokenů, jaké modely, jaké tools, kteří agenti. Business intelligence nad agentic workloads.
🔑
Cloud KMS credentials
Tool credentials (API klíče, service accounts) jsou uloženy v Cloud KMS — ne v agent konfiguraci.
🔄
Portabilita definic
Buildni lokálně (SDK), shipni na platformu (Enterprise). Security tým dostane kontroly bez přepisování agenta.
🏢
Competitive edge oproti Cursor a Windsurf

Cursor nemá enterprise platformu této hloubky. Windsurf je blíže, ale chybí Google Cloud surface. Pro Google Cloud shops Enterprise tier mění celou rovnici — security a compliance requirements jsou splněny out-of-the-box.

Migrace z Gemini CLI

🚨
Deadline: 18. června 2026

Consumer access ke Gemini CLI a Gemini Code Assist IDE extensions skončí 18. 6. 2026 pro všechny uživatele — AI Pro, AI Ultra i free tier. Nastav si připomínku!

Co se vypíná

  • Gemini CLI — terminálový příkaz gemini přestane fungovat
  • Gemini Code Assist VS Code extension — inline suggestions v editoru skončí
  • Gemini Code Assist JetBrains plugin — totéž

Migrační kroky

1
Instaluj Antigravity CLI

Spusť: curl -sSL https://antigravity.google/install.sh | bash

Ověř: antigravity --version

2
Přenes skripty a aliasy

Každý gemini run "..." nahraď za antigravity agent run "...". Většina příkazů má přímý ekvivalent.

3
Aktualizuj CI/CD pipeline

GitHub Actions, GitLab CI a jiné pipeline soubory — nahraď Gemini CLI příkazy za Antigravity CLI. Nová CLI používá stejný API klíč jako Gemini.

4
Odinstaluj Gemini Code Assist extension

V VS Code: Extensions → vyhledej "Gemini Code Assist" → Uninstall. Nahraď Antigravity IDE nebo nech Antigravity 2.0 jako standalone orchestrátor vedle libovolného editoru.

5
Otestuj před deadlinem

Spusť paralelně oba nástroje na stejném projektu ještě před 18. 6. — ověř že výstupy jsou ekvivalentní a všechna CI přechází.

Praktické příklady & best practices

Vzorce které fungují

✓
Specifický task s kontextem souboru

"V souboru src/auth/middleware.ts na řádku 48 přidej rate limiting. Limit: 100 requestů za minutu na IP. Použij existující Redis client z src/lib/redis.ts. Přidej unit test do tests/auth/middleware.test.ts."

✓
Task s definovaným výsledkem

"Refaktoruj src/utils/api.ts: odděl fetch logiku do api-client.ts. Výsledek: api.ts = business logika, api-client.ts = HTTP klient. Všechny existující testy musí projít."

✓
Multi-service audit (využij subagenty)

"Zkontroluj všechny microservices v ./services/ jestli správně validují JWT tokeny. Vytvoř report pro každou službu a souhrnný Markdown dokument."

→ Antigravity automaticky spawnuje subagenta pro každou službu paralelně.

⚠️
Vyhni se vágním taskům

❌ "Vylepši kód"
❌ "Oprav to"
❌ "Udělej to lépe"

Agent neví co znamená "lépe". Vždy specifikuj: co, kde, jak, a jaký je očekávaný výsledek.

Scheduled tasks — best practices

# Nightly dependency check — každou noc ve 3:00 antigravity schedule add \ --cron "0 3 * * *" \ --task "Check for outdated dependencies in package.json, create PR with updates if any found" # Weekly security scan — každé pondělí ráno antigravity schedule add \ --cron "0 8 * * 1" \ --task "Run OWASP dependency check, scan for known CVEs, create issue if severity > high" # Post-release cleanup — po každém merge do main # (via webhook trigger, ne cron) antigravity trigger add \ --event git.merge \ --branch main \ --task "Clean up feature flags older than 30 days, create PR"

Artifacts — jak je číst

Každý agent task generuje Artifacts panel s těmito sekcemi:

📋
PLAN Artifact
Zobrazí se PŘED provedením. Vidíš co agent plánuje udělat. Schválíš nebo odmítneš. Nikdy se nic nemění bez tvého OK.
📝
DIFF Artifact
Přesně co se změnilo v jakém souboru. Klasický git diff formát — zelená přidáno, červená odebrána.

Omezení & known issues

🚨
Usage limits a cooldowns

Gemini 3.5 Pro Eye má usage limits. Heavy users (parallel subagents, voice sessions, scheduled tasks souběžně) narazí na dočasné cooldowns. Řešení: přepni na Claude 4.5 nebo počkej na obnovení kvóty. Ultra plán dává 5× headroom.

⚠️
Složitá prostředí

Velmi custom build environments, obscure frameworky nebo masivní legacy codebases mohou způsobit problémy. Agent může selhat nebo vygenerovat nekorektní kód při práci s nestandartními nástroji. Vždy kontroluj PLAN před schválením.

⚠️
Managed Agents latence

Long-running Managed Agents tasky mohou trvat minuty. Při vývoji frontendu nezapomeň na async handling — app musí zvládnout čekat na response. Použij mock response pro development.

ℹ️
SDK Gemini optimalizace

SDK je optimalizovaný pro Gemini modely. Při použití Claude nebo GPT přes SDK neočekávej stejnou latenci ani cenu — optimalizace cache hits a tool-call pipeline fungují pouze s Gemini family.

Srovnání omezení vs. konkurence

  • VS Code chybí nativně — Antigravity 2.0 standalone app není VS Code fork. Uživatelé zvyklí na VS Code prostředí musí adoptovat dual-wield nebo přejít na Antigravity IDE (v1.0 style)
  • Editor familiarity — Cursor stále vede v čistém code-completion UX pro VS Code uživatele
  • Headless CLI maturity — Claude Code má větší maturitu jako headless CLI agent pro specifické use-cases
  • Vendor lock-in — Google Cloud integrace jsou výhoda pro GCP uživatele, ale komplikace pro AWS/Azure-first shops
